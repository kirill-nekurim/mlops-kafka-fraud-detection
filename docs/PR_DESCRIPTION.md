## Мониторинг потокового антифрода

Добавлены Prometheus, Grafana и Node Exporter к Kafka-скорингу и переобучению
в Airflow. Три дашборда показывают скорость и задержки обработки/записи, скоры,
фрод и системные ресурсы. PostgreSQL-панели включают фильтры штата/мерчанта,
статистику версий, категории последних 1000 операций и сумму подозрительных операций.

Горячая загрузка модели создаёт аннотацию примерно на 30 секунд. Два алерта
загружаются автоматически. Дополнительная метрика — задержка от скоринга до БД.
Метрики записи учитывают успешные новые строки; повторы считаются отдельно.
Миграция поддерживает существующую таблицу scores, Grafana читает её отдельным
пользователем без права записи. Генератор обеспечивает непрерывный поток из CSV.

Проверено: три UP-target, 24 панели, SQL с All и конкретными фильтрами, срабатывание
и восстановление обоих алертов, реальное переобучение и hot reload без перезапуска,
защита от повторной доставки, первый запуск и повторная миграция старой схемы,
тест сохранения прежней модели при повреждённом файле.

Результаты и скриншоты: [docs/VALIDATION.md](https://github.com/kirill-nekurim/mlops-kafka-fraud-detection/blob/hw5-monitoring/docs/VALIDATION.md).
Команды запуска и ручной проверки: [README.md](https://github.com/kirill-nekurim/mlops-kafka-fraud-detection/blob/hw5-monitoring/README.md).
Kafka UI и Streamlit отвечают на health endpoints; Airflow отдельно вернул healthy.
Для полного стека с переобучением нужен запас памяти Docker 4–6 ГБ: при текущих
2.84 GiB полный длительный прогон не подтверждён. В README есть команда запуска
без дополнительных интерфейсов; ограничение записано в отчёте проверки.
